Leakage-Safe Autoresearch for Time-Series LightGBM

How to adapt the autonomous “propose → train → evaluate → keep/revert” loop to temporal, panel, event-driven, and irregularly sampled data without turning the research agent into a leakage generator.

The central design goal is maximum safe autonomy under a frozen point-in-time evaluation contract.

1. The idea

Karpathy’s autoresearch reduces research to a small loop: keep data/evaluation fixed, let an agent modify the trainable system, run an experiment, inspect a frozen validation metric, keep improvements, revert regressions, and repeat.

Read current best→Form hypothesis→Edit candidate→Train→Evaluate→Keep / revert→Log belief
Time-series adaptation: keep the loop, but move the safety boundary outward. Splits, information availability, label availability, purge rules, fold-specific fitting, evaluation metrics, and leakage tests must be immutable.

2. Why temporal autoresearch is harder

Feature leakage

Rolling statistics, group aggregates, normalization, residual features, and as-of joins can silently see the future.

Label overlap

Forward-looking labels near a split boundary can overlap the evaluation period.

Adaptive validation

Thousands of agent queries to one visible validation set create research-overfitting even without row-level leakage.

Irregular time

Lag 1 may mean seconds for one entity and days for another; actual elapsed time must be explicit.

Delayed availability

Event time, report/publication time, label-availability time, and prediction time may differ.

Panel structure

Cross-entity features can leak current or future rows unless exclusion and timing rules are explicit.

3. Freeze the research contract

The agent optimizes inside a sealed temporal evaluation system; it cannot improve the benchmark itself.

4. Use four evaluation levels

historical time ─────────────────────────────────────────────────────────────►

[ fit ][ purge ][ early-stop ][ gap ][ score ]      research fold 1
       [ fit ........ ][ purge ][ early-stop ][ gap ][ score ]   fold 2
                  [ fit ............ ][ purge ][ early-stop ][ gap ][ score ] fold 3

                                      [ SEALED SHADOW HOLDOUT ]
                                                   [ FINAL TEST ]
  • Fit: model fitting and all learned preprocessing.
  • Early-stop: chooses LightGBM best iteration. Strict mode keeps this separate from the research score period.
  • Research score: visible to the agent and used for keep/revert.
  • Shadow holdout: queried only for promotion and kept out of the agent prompt.
  • Final test: opened once after the campaign ends.
Do not let the agent redefine dates after seeing results. Changing the split is changing the benchmark.

5. Purge by information overlap

keep training row i only if:

label_end_time_i < evaluation_start_time

and every feature satisfies:

feature_available_time <= prediction_time_i

For irregular timestamps, define purge/embargo in clock time or directly through label-interval overlap—not by dropping an arbitrary number of rows.

6. Expand agent freedom in tiers

TierAgent may changeRiskUse
0LightGBM hyperparameters onlyLowFirst campaign
1Parameters + safe feature selectionLow–mediumDefault practical mode
2Feature recipes in a restricted temporal DSLMediumFeature discovery
3Arbitrary feature codeHighOnly with strong tests + human promotion

Example temporal DSL

Lag("x", entity="id", events=1)
TimeSinceLast("event", entity="id")
RollingPast("x", entity="id", window="5min", agg="mean", closed="left")
EWMPast("x", entity="id", half_life="2min", available_time="report_time")
AsOf("source", on="prediction_time", direction="backward")
GroupState("x", group="sector", exclude_current_entity=True, half_life="10min")
MissingAge("source_timestamp", now="prediction_time")

The agent selects recipes; immutable code compiles them. This is safer than free-form joins and rolling code.

7. Run leakage tests before every fit

A. Future-append invariance

past = raw[raw.event_time <= cutoff]
X_past = build_features(past, predictions_up_to_cutoff)
X_full = build_features(raw, predictions_up_to_cutoff)
assert_equivalent(X_past, X_full)

B. Source-time audit

assert (feature_source_available_time <= prediction_time).all()

C. Label firewall

FORBIDDEN = {"target", "future_target", "label_end_time", "post_event_value"}
assert not (set(X.columns) & FORBIDDEN)

D. Fold-fit scope

Encoders, imputers, category maps, target statistics, feature selection, learned bias/residual baselines, and any fitted transformation must use the training portion of the fold only.

E. Residual availability

A residual is usable only after its true label becomes observable: residual_available_time < prediction_time.

F. Split-hash guard

Hash evaluation row IDs and timestamps. Any candidate that changes evaluation membership fails.

8. Use one frozen score plus hard gates

For research fold f:
relative_loss_f = candidate_loss_f / frozen_baseline_loss_f

research_score = median(relative_loss_f)     # lower is better

accept only if:
  research_score < best_score - epsilon
  AND candidate wins on enough folds
  AND no critical segment exceeds regression tolerance
  AND runtime / memory constraints pass
  AND all leakage tests pass

Use paired observations for candidate-vs-baseline comparisons. Save expensive block/bootstrap uncertainty checks for promotion candidates.

9. The autonomous loop

while experiment_budget_remaining:
    read(program.md, current best, recent results)
    hypothesis = propose_one_change()
    edit(experiment.py)

    if not run_leakage_tests().pass:
        log("reject: leakage")
        revert()
        continue

    result = run_frozen_walk_forward_evaluation()

    if result.score_improved and result.all_gates_pass:
        commit_candidate_as_best()
        log("keep", hypothesis, result)
    else:
        revert()
        log("reject", hypothesis, result)

    update_beliefs_from_outcome()
One experiment, one main hypothesis. Large multi-change edits make wins hard to attribute and reduce research efficiency.

Reproducibility defaults

    "seed": 20260817,

When tuning min_data_in_leaf while reusing a LightGBM Dataset, account for feature_pre_filter. LightGBM documents that features can be filtered based on min_data_in_leaf; either rebuild the Dataset for each candidate or deliberately configure around this behavior.

If early stopping is part of the harness, freeze metric ordering and consider first_metric_only so adding diagnostics does not alter stopping behavior. Treat dart as a separate branch because LightGBM’s standard early-stopping callback does not operate in DART mode.

11. Feature autoresearch candidates

Recency

Time since last observation, source age, staleness flags.

Continuous-time state

EWMA / exponential decay using actual elapsed time.

Event state

Previous values, event counts, bursts, recent direction.

Group state

Past-only cross-entity signals, ideally excluding the current entity.

Calendar regime

Time-of-day, seasonality, schedules, known regime variables.

Data quality

Missingness, source count, freshness, disagreement, uncertainty proxies.

Residual-to-feature research

S_i(tau) =
sum_j exp(-(prediction_time_i - residual_available_time_j)/tau) * residual_j
------------------------------------------------------------------------
sum_j exp(-(prediction_time_i - residual_available_time_j)/tau)

where residual_available_time_j < prediction_time_i

Search a small ladder of half-lives first. Do not optimize a continuous half-life to arbitrary precision on the same visible research folds.

12. Prevent autoresearch-overfitting

  1. Use several chronological research folds.
  2. Keep a sealed shadow period outside the agent-readable workspace.
  3. Limit shadow queries to promoted candidates or campaign checkpoints.
  4. Do not feed detailed shadow metrics back into the autonomous prompt.
  5. Keep one final test period unopened until the campaign ends.
  6. Record the total number of attempted experiments; a tiny gain after 3 trials is different evidence from the same gain after 3,000 adaptive trials.

  "decision": "KEEP",
  "belief_update": "short-horizon state appears useful; test nearby half-life"
}

The ledger gives the agent memory and discourages repeated failed ideas.

15. Example program.md

# Objective
Improve frozen time-series research_score for LightGBM.

# You may edit
- experiment.py only.

# You may change
- bounded LightGBM parameters
- feature selection from SAFE_FEATURES
- feature recipes from the approved temporal DSL

# You may not change
- prepare.py
- evaluate.py
- leakage_tests.py
- data_contract.yaml
- splits.json
- primary metric
- research fold dates
- purge / embargo rules
- shadow or final holdout files

# Research rules
1. One main hypothesis per experiment.
2. Run leakage tests before training.
3. Never use information whose available_time is after prediction_time.
4. Never use shadow/final scores to guide the loop.
5. Keep only if the frozen score improves and all gates pass.
6. Revert failed experiments.
7. Append every result and belief update to results.jsonl.
8. Prefer simple explanations before adding complexity.
9. Stop if improvements plateau or the experiment budget is reached.

16. Recommended campaign order

  1. Campaign 1 — LightGBM-only: bounded tree complexity, regularization, sampling, learning rate, early stopping on frozen safe features.
  2. Campaign 2 — feature selection: add/drop already point-in-time-safe feature families.
  3. Campaign 3 — temporal DSL: autonomously search lags, rolling windows, continuous-time decay, recency, group states.
  4. Campaign 4 — residual research: build residual-derived states from historical OOS residuals with explicit availability times.
  5. Campaign 5 — specialized objectives/interactions: only after the harness survives earlier campaigns.
Expand autonomy gradually. First prove the benchmark is hard to cheat; then enlarge the search space.

17. Promotion checklist

  • Leakage tests pass.
  • Primary research score improves.
  • Gain is not driven by one temporal fold.
  • Critical segments remain within regression tolerances.
  • Result is robust to reasonable timestamp / delay / missingness definitions.
  • The residual pattern targeted by the hypothesis weakens.
  • Runtime and memory constraints pass.
  • Shadow holdout supports the result.
  • Final test is still untouched.
