Dealer Run Point-in-Time Feature Engine

Detailed implementation review of the new state/flow design. This version emphasizes semantic correctness, common-size dealer comparison, quantity handling, leakage-safe normalization, event counting, regression tests, and code that is close to drop-in.

0. Executive summary

ArchitectureKeep the observation-time state/flow split.
Highest-priority fixDefine a canonical quote event and common-size ladder state.
Next optimizationOnly after semantics are frozen, replace repeated scans with timestamp indexing/state machines.

The new implementation is substantially better than a quote-timestamp rolling table followed by merge_asof: features are now constructed at each observation time, current state is separated from trailing activity, and freshness is explicit. The remaining risks are mostly about what one row means, what one update means, and how quantity tiers should be compared across dealers.

Recommended design principle: represent dealer-run data as three objects: current state, trailing event flow, and data-quality/freshness. Do not let a raw vendor row play all three roles.

2. Canonical row and event model

The first improvement should be to separate vendor rows from dealer update events. A row is useful for ladder construction; an event is useful for activity/repricing flow.

2.1 Revised quote preparation

_quantity_feature_utils.py replacement for prepare_quantity_quote_rows
def prepare_quantity_quote_rows(
    quotes: pd.DataFrame,
    *,
    timestamp_col: str = "quote_timestamp_UTC",
    cusip_col: str = "cusip",
    firm_col: str = "firm",
    side_col: str = "side",
    price_type_col: str = "price_type",
    quantity_col: str = "quantity",
    price_col: str = "price",
    spread_col: str = "spread",
) -> pd.DataFrame:
    """Normalize long dealer-run rows without destroying source semantics."""
    work = quotes.copy()
    work[timestamp_col] = pd.to_datetime(work[timestamp_col], utc=True, errors="coerce")
    work[cusip_col] = work[cusip_col].astype("string")
    work[firm_col] = work[firm_col].astype("string")
    work[side_col] = work[side_col].astype("string").str.lower()
    work[price_type_col] = work[price_type_col].astype("string").str.lower()
    work[quantity_col] = pd.to_numeric(work[quantity_col], errors="coerce")
    work[price_col] = pd.to_numeric(work[price_col], errors="coerce")
    work[spread_col] = pd.to_numeric(work[spread_col], errors="coerce")

    valid = (
        work[timestamp_col].notna()
        & work[cusip_col].notna()
        & work[firm_col].notna()
        & work[side_col].isin(["bid", "ask"])
        & work[price_type_col].isin(["price", "spread"])
    )
    work = work.loc[valid].copy()

    q = work[quantity_col]
    work["quote_qty_raw"] = q
    work["quote_qty_observed"] = q.notna()
    work["quote_qty_positive"] = q.gt(0)
    work["quote_qty_zero"] = q.eq(0)
    work["quote_qty_invalid_negative"] = q.lt(0)
    work["quote_qty_clean"] = q.where(q.gt(0))
    work["log_quote_qty_clean"] = np.log1p(work["quote_qty_clean"])

    work["quote_price_value"] = work[price_col].where(work[price_type_col].eq("price"))
    work["quote_spread_value"] = work[spread_col].where(work[price_type_col].eq("spread"))

    return work.sort_values(
        [cusip_col, timestamp_col, firm_col, side_col, price_type_col], kind="stable"
    ).reset_index(drop=True)

2.2 Event table: count messages, not ladder rows

The correct event key is vendor-specific. If there is a source message/sequence ID, use it. If not, define an explicit fallback and document the assumption.

_quantity_feature_utils.py new helper
def build_quote_event_table(
    rows: pd.DataFrame,
    *,
    firm_col: str,
    timestamp_col: str,
    side_col: str,
    event_id_col: str | None = None,
    collapse_price_spread_views: bool = True,
    price_type_col: str = "price_type",
) -> pd.DataFrame:
    """Return one representative row per dealer update event.

    Prefer a vendor message/sequence id. The fallback below assumes rows
    with the same dealer/timestamp/side belong to one logical update.
    """
    if rows.empty:
        return rows.copy()
    x = rows.sort_values(timestamp_col, kind="stable").copy()
    if event_id_col and event_id_col in x.columns:
        keys = [event_id_col]
    else:
        keys = [firm_col, timestamp_col, side_col]
        if not collapse_price_spread_views:
            keys.append(price_type_col)
    return x.drop_duplicates(keys, keep="last").reset_index(drop=True)
Important: same timestamp = same event is only a fallback assumption. Verify vendor message semantics before using the resulting event-count features.

3.2 Snapshot-feed implementation

_quantity_feature_utils.py snapshot semantics
def latest_snapshot_state_rows(
    rows: pd.DataFrame,
    observation_time: pd.Timestamp,
    *,
    timestamp_col: str,
    firm_col: str,
    side_col: str,
    price_type_col: str,
    max_age: str | pd.Timedelta | None,
    allow_exact_matches: bool = False,
) -> pd.DataFrame:
    if rows.empty or pd.isna(observation_time):
        return rows.iloc[0:0].copy()

    eligible = (
        rows[timestamp_col].le(observation_time)
        if allow_exact_matches
        else rows[timestamp_col].lt(observation_time)
    )
    if max_age is not None:
        eligible &= rows[timestamp_col].gt(observation_time - pd.Timedelta(max_age))

    x = rows.loc[eligible].copy()
    if x.empty:
        return x

    state_keys = [firm_col, side_col, price_type_col]
    latest_ts = x.groupby(state_keys, dropna=False)[timestamp_col].transform("max")
    state = x.loc[x[timestamp_col].eq(latest_ts)].copy()
    state["quote_age_seconds"] = (
        observation_time - state[timestamp_col]
    ).dt.total_seconds()
    return state

3.3 Incremental-tier feed implementation

If only one quantity tier is updated at a time, the state key must include a stable tier identifier.

_quantity_feature_utils.py incremental semantics
def latest_incremental_tier_state_rows(
    rows: pd.DataFrame,
    observation_time: pd.Timestamp,
    *,
    timestamp_col: str,
    firm_col: str,
    side_col: str,
    price_type_col: str,
    tier_id_col: str,
    max_age: str | pd.Timedelta | None,
) -> pd.DataFrame:
    x = rows.loc[rows[timestamp_col].lt(observation_time)].copy()
    if max_age is not None:
        x = x.loc[x[timestamp_col].gt(observation_time - pd.Timedelta(max_age))]
    if x.empty:
        return x

    keys = [firm_col, side_col, price_type_col, tier_id_col]
    idx = x.groupby(keys, dropna=False)[timestamp_col].idxmax()
    state = x.loc[idx].copy()
    state["quote_age_seconds"] = (
        observation_time - state[timestamp_col]
    ).dt.total_seconds()
    return state.sort_values(keys)

4. Common-size ladder features

The most important cross-dealer correction is to compare quote values at the same displayed size.

4.1 Interpolate one dealer ladder

_quantity_feature_utils.py new helper
def quote_at_target_size(
    rows: pd.DataFrame,
    target_qty: float,
    *,
    qty_col: str = "quote_qty_clean",
    value_col: str,
    allow_extrapolation: bool = False,
) -> float:
    x = (
        rows[[qty_col, value_col]]
        .dropna()
        .groupby(qty_col, as_index=False)[value_col]
        .median()
        .sort_values(qty_col)
    )
    if len(x) < 2 or target_qty <= 0:
        return np.nan

    qty = x[qty_col].to_numpy(dtype="float64")
    val = x[value_col].to_numpy(dtype="float64")
    if not allow_extrapolation and not (qty[0] <= target_qty <= qty[-1]):
        return np.nan

    return float(np.interp(np.log(target_qty), np.log(qty), val))

4.2 Dealer × common-size table

_quantity_feature_utils.py new helper
def dealer_values_at_common_sizes(
    rows: pd.DataFrame,
    *,
    target_sizes: tuple[int, ...],
    firm_col: str,
    value_col: str,
    qty_col: str = "quote_qty_clean",
) -> pd.DataFrame:
    out = []
    for firm, dealer_rows in rows.groupby(firm_col, dropna=True, sort=False):
        rec = {firm_col: firm}
        for size in target_sizes:
            rec[f"value_{size}"] = quote_at_target_size(
                dealer_rows,
                target_qty=size,
                qty_col=qty_col,
                value_col=value_col,
                allow_extrapolation=False,
            )
        out.append(rec)
    return pd.DataFrame(out)

    x = values.dropna()
    if x.empty:

5. Quantity features: preserve meaning, then normalize

If each dealer contributes its maximum positive displayed quantity, prefer names such as current_capacity_sum, current_capacity_median, capacity_hhi, and effective_capacity_dealers.

5.1 Capacity concentration

_quantity_feature_utils.py cleaned concentration helper
def quantity_concentration(max_quantities: pd.Series) -> dict[str, float]:
    q = max_quantities.dropna().astype(float)
    q = q[q > 0]
    total = q.sum()
    if q.empty or total <= 0:
        return {
            "largest_dealer_share": np.nan,
            "top3_dealer_share": np.nan,
            "capacity_hhi": np.nan,
            "effective_capacity_dealers": np.nan,
            "n_dealers_for_80pct_capacity": np.nan,
        }

    share = (q / total).sort_values(ascending=False)
    hhi = float((share ** 2).sum())
    return {
        "largest_dealer_share": float(share.iloc[0]),
        "top3_dealer_share": float(share.head(3).sum()),
        "capacity_hhi": hhi,
        "effective_capacity_dealers": 1.0 / hhi if hhi > 0 else np.nan,
        "n_dealers_for_80pct_capacity": int((share.cumsum() < 0.8).sum() + 1),
    }

5.2 Leakage-safe relative quantity

feature preprocessing strictly point-in-time
def add_past_relative_quantity(
    rows: pd.DataFrame,
    *,
    group_cols: list[str],
    timestamp_col: str,
    log_qty_col: str = "log_quote_qty_clean",
    min_periods: int = 20,
) -> pd.DataFrame:
    x = rows.sort_values([*group_cols, timestamp_col]).copy()
    g = x.groupby(group_cols, dropna=False)[log_qty_col]

    # strictly earlier observations only
    past_median = g.transform(
        lambda s: s.shift().expanding(min_periods=min_periods).median()
    )
    x["log_qty_minus_past_median"] = x[log_qty_col] - past_median
    return x

6. Freshness and pair synchronization

Overall dealer age is useful, but it should not replace side/type freshness.

_quantity_feature_utils.py slice freshness
def add_slice_freshness(
    record: dict[str, float],
    rows: pd.DataFrame,
    *,
    prefix: str,
    firm_col: str,
    age_col: str = "quote_age_seconds",
    buckets: tuple[str, ...] = ("1min", "5min", "15min"),
) -> None:
    if rows.empty:
        record[f"{prefix}_dealer_count"] = 0
        return

    age = rows.groupby(firm_col, dropna=True)[age_col].min().dropna()
    record[f"{prefix}_dealer_count"] = len(age)
    record[f"{prefix}_age_median_seconds"] = age.median() if len(age) else np.nan
    record[f"{prefix}_age_p90_seconds"] = age.quantile(.9) if len(age) else np.nan
    record[f"{prefix}_age_max_seconds"] = age.max() if len(age) else np.nan
    for bucket in buckets:
        sec = pd.Timedelta(bucket).total_seconds()
        record[f"{prefix}_share_dealers_fresh_{bucket}"] = age.le(sec).mean() if len(age) else np.nan

6.1 Two-sided synchronization

_quantity_feature_utils.py pair quality
def dealer_pair_quality(
    spread_state_rows: pd.DataFrame,
    *,
    firm_col: str,
    side_col: str,
    timestamp_col: str,
    max_pair_age: str | pd.Timedelta = "15min",
) -> pd.DataFrame:
    out = []
    max_gap = pd.Timedelta(max_pair_age).total_seconds()
    for firm, g in spread_state_rows.groupby(firm_col, dropna=True, sort=False):
        bid = g.loc[g[side_col].eq("bid")]
        ask = g.loc[g[side_col].eq("ask")]
        if bid.empty or ask.empty:
            continue
        bid_ts = bid[timestamp_col].max()
        ask_ts = ask[timestamp_col].max()
        gap = abs((bid_ts - ask_ts).total_seconds())
        out.append({
            firm_col: firm,
            "pair_leg_gap_seconds": gap,
            "pair_is_synchronized": gap <= max_gap,
        })
    return pd.DataFrame(out)

7.2 Event-level repricing

_quantity_feature_utils.py revision features
def add_revision_features(
    record: dict[str, float],
    event_values: pd.DataFrame,
    *,
    prefix: str,
    firm_col: str,
    side_col: str,
    timestamp_col: str,
    value_col: str = "event_common_size_value",
) -> None:
    if event_values.empty:
        return

    keys = [firm_col, side_col]
    x = event_values.sort_values([*keys, timestamp_col]).copy()
    x["delta"] = x.groupby(keys, dropna=False)[value_col].diff()
    d = x.dropna(subset=["delta"])
    if d.empty:
        return

    record[f"{prefix}_revision_count"] = len(d)
    record[f"{prefix}_revision_abs_median"] = d["delta"].abs().median()
    record[f"{prefix}_revision_abs_p90"] = d["delta"].abs().quantile(.9)
    record[f"{prefix}_revision_breadth"] = float(np.sign(d["delta"]).mean())

    dealer_sign = d.groupby(firm_col)["delta"].mean().pipe(np.sign)
    record[f"{prefix}_dealer_revision_breadth"] = (
        float(dealer_sign.mean()) if len(dealer_sign) else np.nan
    )

8. Recommended builder structure

The public function can remain compact. Put semantics in helpers and keep one clear path from observation → current state → current-state features → trailing flow.

quantity_features.py recommended skeleton
def build_dealer_run_observation_features(
    quotes: pd.DataFrame,
    observations: pd.DataFrame,
    *,
    windows: tuple[str, ...] = ("5min", "30min", "60min"),
    target_sizes: tuple[int, ...] = (100_000, 250_000, 500_000, 1_000_000),
    dealer_state_max_age: str | pd.Timedelta = "60min",
    allow_exact_matches: bool = False,
    feed_semantics: str = "snapshot",   # or "incremental"
    tier_id_col: str | None = None,
    ...,
) -> pd.DataFrame:
    quote_rows = prepare_quantity_quote_rows(quotes, ...)
    obs = observations.copy().reset_index(drop=True)
    obs["_obs_id"] = np.arange(len(obs))
    obs["_obs_ts_utc"] = _to_utc_timestamp(obs[observation_time_col], ...)

    quote_groups = {
        key: g.sort_values(timestamp_col, kind="stable").reset_index(drop=True)
        for key, g in quote_rows.groupby(cusip_col, sort=False)
    }

    records = []
    for row in obs.itertuples(index=False):
        obs_id = getattr(row, "_obs_id")
        cusip = getattr(row, "_obs_cusip")
        t = getattr(row, "_obs_ts_utc")
        rows = quote_groups.get(cusip)
        rec = {"_obs_id": obs_id}

        if rows is None or pd.isna(t):
            records.append(rec)
            continue

        state = build_current_state(
            rows,
            t,
            feed_semantics=feed_semantics,
            tier_id_col=tier_id_col,
            max_age=dealer_state_max_age,
            allow_exact_matches=allow_exact_matches,
            ...,
        )
        add_current_state_features(rec, state, target_sizes=target_sizes, ...)
        add_trailing_flow_features(rec, rows, t, windows=windows, target_sizes=target_sizes, ...)
        records.append(rec)

    features = pd.DataFrame(records)
    return (
        obs.merge(features, on="_obs_id", how="left")
        .drop(columns=["_obs_id", "_obs_ts_utc"], errors="ignore")
    )

itertuples() is preferable to iterrows() for the clear baseline implementation. The bigger performance gain comes from avoiding repeated full-history scans.

9. Performance path without changing semantics

9.1 First optimization: timestamp slicing with searchsorted

_quantity_feature_utils.py fast local slicing
def slice_time_window(
    rows: pd.DataFrame,
    times_ns: np.ndarray,
    *,
    start: pd.Timestamp,
    end: pd.Timestamp,
    include_end: bool = False,
) -> pd.DataFrame:
    left = np.searchsorted(times_ns, start.value, side="right")
    right = np.searchsorted(
        times_ns,
        end.value,
        side="right" if include_end else "left",
    )
    return rows.iloc[left:right]

# Build once per sorted instrument.

    end=observation_time,
    include_end=False,
)

9.2 Second optimization: incremental state machine

After snapshot/incremental semantics and feature definitions are frozen, process quotes and observations together in time order. Maintain a latest-state dictionary and rolling deques. This moves the design toward approximately linear processing in quotes plus observations.

        f1.loc[0, feature_cols], f2.loc[0, feature_cols], check_names=False

11. Recommended implementation order

  1. Confirm feed semantics: full ladder snapshots vs incremental tier updates; zero-size meaning; price/spread relationship; event/message identifiers.
  2. Fix event counting and quantity flags.
  3. Switch ladder-based cross-dealer features to common target sizes.
  4. Make exact-timestamp policy explicit and add leakage tests.
  5. Add side/type freshness and pair synchronization.
  6. Add past-relative quantity and event-level repricing features.
  7. Only then optimize with searchsorted/incremental state.
Bottom line: the current implementation is directionally correct. The next improvements should make state/event semantics exact and make dealers comparable at a common quantity. That is more valuable than adding another large batch of generic rolling moments.
