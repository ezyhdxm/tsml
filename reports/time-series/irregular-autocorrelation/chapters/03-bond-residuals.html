Corporate-bond residual：如何把问题定义对

  • 9.2 Event-time 与 clock-time
  • 9.3 两种 pooled estimand
  • 9.4 Informative observation process
  • 9.5 Overlapping targets
  • 9.6 数据与 pipeline audit

设 out-of-sample prediction residual 为

\[e_{b,i}=y_{b,i}-\widehat y_{b,i},\]

其中 \(b\) 表示 CUSIP，timestamp 为 \(t_{b,i}\)。真正困难的不是把某个 ACF 函数跑出来，而是先确定哪些 rows 构成同一条 time series、lag 使用哪一种 clock、以及 pooling 对活跃 bonds 给了多少权重。

9.1 Pair 必须在同一条 series 内

最基本约束是

\[b_i=b_j.\]

把 CUSIP A 在 10:00 的 residual 与 CUSIP B 在 10:30 的 residual 组成 pair，估计的是 cross-sectional 或 common-factor dependence，不是同 bond autocorrelation。

还要明确是否允许跨 session：

  • Calendar-clock：overnight 也算真实经过时间，适合研究 wall-clock persistence，但 closed hours 的经济含义要单独解释。
  • Session-clock：只在同一交易日或 active session 内构造 pairs，适合研究交易发生后的 correction。
  • Business-clock：用 \(s(t)=\int_0^t \mathbf 1\{u\text{ is active market time}\}\,du\) 排除闭市时间。

这三种 clock 对同一数据可以产生不同 ACF；它们不是“参数选择”，而是不同 estimands。

9.2 同时报告 event-time 与 clock-time

curvelag业务解释
event-time ACF1, 2, 5 trades需要几笔新交易，模型误差才被吸收？
clock-time ACF5m, 30m, 1hmispricing 在真实时间中持续多久？

若 event-time decay 很快而 clock-time decay 很慢，可能只是该 bond 很少交易；若 clock-time decay 快但 event-time decay 慢，可能说明活跃时段连续 trades 共享相似 microstructure effects。二者不应互相替代。

9.3 Pooled ACF 有至少两种不同 estimand

Pair-weighted pooling

\[\widehat\rho_{\mathrm{pair}}(\tau)\propto \sum_b\sum_{i<j\in b}w_{bij}(\tau)z_{bi}z_{bj}.\]

活跃 bonds 产生更多 pairs，所以主导结果。它回答：随机抽取一个 eligible observed pair 时，平均 dependence 是什么？

Bond-equal pooling

先估计每只 bond 的 curve，再平均：

\[\widehat\rho_{\mathrm{bond}}(\tau)=\frac1B\sum_{b=1}^B\widehat\rho_b(\tau).\]

它回答：随机抽取一只 bond 时，平均 dependence 是什么？但 sparse bonds 的单独 estimate 很噪，应设置 minimum support 或使用 hierarchical shrinkage。报告里应明确 weighting；仅写“pooled ACF”是不够的。

9.4 Observation process 是数据的一部分

交易强度会随 volatility、news、inventory pressure 和 disagreement 变化，因此 pair-weighted estimate 还隐含地提高了 high-activity states 的权重。建议至少比较：

  1. Raw pair-weighted：真实 observed-pair diagnostic。
  2. Anchor-balanced：每个 anchor、每个目标 lag 至多选择一个 nearest match，接近 S-ACF 的 weighting。
  3. Inverse-intensity weighted：只有在 observation-intensity model 可信时使用，并把它作为 sensitivity，而不是替代 raw result。

若 observation times informative，直接曲线更稳妥的解释是“条件于两端均有交易被观测时的 residual persistence”，而不是无条件 latent fair-value process 的结构 ACF。

9.5 Overlapping target 会机械制造 autocorrelation

若 target 是固定 horizon return 或 spread change

\[Y_t^{(H)}=P_{t+H}-P_t,\]

相邻 samples 的 target windows 可能重叠。即使 \(P_t\) 有独立、同方差 increments，在 Brownian idealization 下，当 \(0<\tau<H\) 时

\[\operatorname{Corr}\!\left(Y_t^{(H)},Y_{t+\tau}^{(H)}\right)=1-\frac{\tau}{H}.\]

推导来自两个 labels 共享长度 \(H-\tau\) 的 future increment。它不是模型遗漏了 persistent signal，而是 label construction 的机械结果。

Residual ACF 必做的 overlap audit

  • 报告 eligible pairs 的 target-window overlap rate；
  • 单独计算 non-overlapping subset ACF；
  • 用“independent increments + 原始 sampling times + 同样 target construction”建立 mechanical null baseline。

9.6 Near-zero-lag correlation 先排查数据问题

异常高的短 lag residual correlation 可能来自：

  • dealer-to-dealer double reporting、duplicate 或 corrected/as-of trades；
  • 同一 client trade 被拆成多个中间 reports；
  • stale benchmark、quote snapshot 或相同 prediction 被复用于邻近 rows；
  • bid/ask direction、quantity 或 transaction cost 未处理；
  • feature windows、prediction horizons 或 labels 在多个 rows 上重叠；
  • 同一 market shock 对许多 bonds 同时产生 common residual。

所以 ACF 是定位 pipeline/model 问题的入口，不是自动的 economic conclusion。

9.7 推荐的主要输出

  1. Sampling-gap distribution 与每 CUSIP/session observation count。
  2. Event-time ACF：\(k=1,2,3,5,10\)。
  3. Clock-time Gaussian-kernel ACF，例如 1 分钟到 4 小时。
  4. 每个 lag 的 pair count 与 weight-concentration curve。
  5. Date/session block 或 multiway cluster bootstrap bands。
  6. Pair-weighted 与 bond-equal/shrunk pooling。
  7. Same-session、calendar-clock 与 business-clock sensitivity。
  8. Target-overlap audit、non-overlap curve 与 mechanical null。
  9. 按 side、liquidity、tenor、rating、time-of-day 分层。
  10. 仅在曲线正、近似单调且单指数合理时报告 OU half-life。
