10. 一套不跳步的实务流程

Step 1：先写一句 estimand

在同一 CUSIP、同一交易 session 内，对 variance-standardized out-of-sample residual，估计随机 observed trade pair 在 clock-time lag \(\tau\) 附近的 pair-weighted correlation。

这句话一次确定了 series、session、conditioning、pooling weight 和 time clock。若其中任何一项改变，估计对象也随之改变。

Step 2：构造可审计 residual

  • 只使用真正 point-in-time、out-of-sample predictions；
  • 固定 sign convention，例如 \(e=y-\widehat y\)；
  • 去除或标记 duplicates、as-of/corrected trades；
  • 使用预测 conditional scale 或稳定 group scale 得到 \(z=e/\widehat\sigma\)；
  • 保留 side、quantity、liquidity、target interval 与 model version 等 audit columns。

Step 3：先看 sampling，再看 ACF

  • 相邻 gap distribution 与长 gap；
  • 每 CUSIP/session observation count；
  • 每个目标 lag 的 eligible pair support；
  • active bursts、overnight gaps 与交易时段结构。

Step 4：计算 event-time ACF

这是最简单的 sanity check，也与普通 .shift(k) 对齐。它应明确命名为 event lag 1/2/5，而不能被改写成“5-minute ACF”。

Step 5：计算 clock-time kernel ACF

  • pairs 限制在同一 CUSIP/session；
  • 使用业务可解释的 lag grid；
  • Gaussian bandwidth 可先设为相邻 grid spacing 的 0.5–1 倍，再做 sensitivity；
  • 同时输出 weighted product mean 与 local-normalized ACF。

Step 6：把 support 和 uncertainty 与曲线放在一起

任何不报告 support 的 irregular ACF 都是不完整的。置信区间必须按 series/session/date blocks，而不是独立重采样 pair products。

Step 7：做 confound audits

至少检查 target overlap、duplicates/clustered reports、common market factor、informative sampling、regime/heteroskedasticity，以及 calendar time 与 business time 的差异。

Step 8：最后才拟合 half-life

只有经验 curve 与

\[\rho(\tau)=e^{-\lambda\tau}\]

大致一致时才报告 \(\log 2/\lambda\)。若有 fast + slow 两段 decay，考虑 two-scale model；若 curve 变负或振荡，使用 CARMA/state-space，而不是对负 correlation 取 log。

11. Python 实现

同目录的 irregular_acf.py 提供：

function用途
standardize_within在指定 group 内中心化和标准化。
build_within_series_pairs只构造 max-lag window 内、同 series 的 pairs。
kernel_acf_from_pairsGaussian、rectangular 或 Epanechnikov clock-time ACF。
event_time_acf按 observation index 计算 event-time ACF。
cluster_bootstrap_acf_from_pairs按 cluster 汇总 pair contributions 后快速 bootstrap。
ou_half_life_from_acf对正且近似单调的 curve 做 descriptive OU fit。

最小使用方式：

from irregular_acf import (
    build_within_series_pairs,
    cluster_bootstrap_acf_from_pairs,
    event_time_acf,
    kernel_acf_from_pairs,
    standardize_within,
)

# Point-in-time residual and session key.
df["resid"] = df["y_true"] - df["y_pred"]
df["trade_date"] = pd.to_datetime(
    df["EFFECTIVE_DATETIME_TS"]
).dt.date
df["series_session"] = (
    df["CUSIP"].astype(str)
    + "|"
    + df["trade_date"].astype(str)
)

# Illustration only: a predicted conditional scale is often better.
df = standardize_within(
    df,
    value_col="resid",
    group_cols=["CUSIP"],
    output_col="z",
)

event = event_time_acf(
    df.sort_values(["series_session", "EFFECTIVE_DATETIME_TS"]),
    value_col="z",
    series_cols=["series_session"],
    max_event_lag=10,
)

pairs, summary = build_within_series_pairs(
    df,
    time_col="EFFECTIVE_DATETIME_TS",
    value_col="z",
    series_cols=["series_session"],
    cluster_cols=["trade_date"],
    max_lag=260,
    time_unit="minutes",
)

lags = [0, 1, 2, 5, 10, 15, 30, 60, 120, 180, 240]
clock = kernel_acf_from_pairs(
    pairs,
    lags=lags,
    bandwidth=5,
    kernel="gaussian",
)

clock_ci = cluster_bootstrap_acf_from_pairs(
    pairs,
    cluster_col="trade_date",
    lags=lags,
    bandwidth=5,
    n_boot=500,
    random_state=7,
)

11.1 复杂度

Naive all-pairs 是 \(O(n^2)\)。实现先按 series/time 排序，并用 searchsorted 只枚举

\[d_{ij}\le L_{\max}\]

的 pairs，因此工作量更接近

\[O(n+P_L),\]

其中 \(P_L\) 是 max-lag window 内真实 eligible pair 数。极高频 burst 中 \(P_L\) 仍可能很大；生产版本应使用 Numba/C++、fine-lag-bin 预聚合，或业务上限制 session/max lag。

11.2 代码无法替你决定的事情

  • 什么才是一条 series；
  • 是否允许 overnight pairs；
  • 用哪一种 conditional scale；
  • bootstrap unit 是 CUSIP、session、date 还是 multiway cluster；
  • pooling 是 pair-weighted 还是 bond-equal；
  • observation-time endogeneity 是否可忽略；
  • target overlap 是否机械制造 persistence。

这些都是 estimand 和识别假设的一部分，不能藏进函数默认值。
